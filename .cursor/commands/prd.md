# PRD作成

## 概要

PRD（Product Requirements Document）を作成するコマンドです。ユーザーの要求を構造化し、開発に必要な要件を明確化します。

## 前提条件

- ユーザーから機能やプロダクトに関する要求が提示されていること
- テンプレート: [assets/prd-template.md](assets/prd-template.md)

## 手順

### Step 1: 要求の理解

ユーザーの要求を以下の観点で整理する：

- **誰のため？** - 主たる利用者・ステークホルダー
- **何を解決？** - 課題・ペインポイント
- **どうなれば成功？** - 期待する成果・ゴール

### Step 2: 不明点の確認

以下の情報が不足している場合、ユーザーに質問する：

- 対象ユーザーと利用シナリオ
- 必須機能（最大3つに絞る）
- 技術的な制約・時間的な制約
- 受け入れ基準

**質問は最小限に留め、1回の対話で必要な情報を収集する。**

### Step 3: PRDの作成

1. テンプレートに沿ってPRDを作成する
2. 推測で補完した項目には `(推測)` を付記する
3. 出力先: `docs/prd.md`

### Step 4: レビュー依頼

作成したPRDをユーザーに提示し、以下を確認する：

- 要件の過不足
- 優先度の妥当性
- 受け入れ基準の明確さ

## 出力形式

```markdown
# PRD: {プロジェクト名}

## 1. Stakeholder
...（テンプレートに従う）
```

## 注意事項

- 機能要件は最大3つに絞る（スコープクリープを防ぐ）
- 受け入れ基準は Given/When/Then 形式で具体的に記述する
- 曖昧な要求は推測せず、まず質問する
