# 技術選定

## 概要

プロトタイプ実装のための技術選定をおこなうコマンドです。ユーザーの要求と技術的背景を考慮し、最適な技術スタックを提案します。

## 前提条件

- ユーザーから機能やプロダクトに関する要求が提示されていること
- PRD があると望ましい（参照: `docs/prd.md`）
- テンプレート: [assets/tech-stack-template.md](assets/tech-stack-template.md)

## 手順

### Step 1: 要求の理解

PRD または会話から以下を把握する：

- **プロダクトの種類**: Webアプリ / モバイル / CLI / API など
- **主要機能**: 必要な技術的機能（認証、DB、リアルタイム通信など）
- **制約**: 時間、予算、デプロイ環境、既存システムとの統合

### Step 2: ユーザーの技術レベルの把握

以下の観点でユーザーの技術的背景を確認する：

- **使用経験のある言語・フレームワーク**: 直接質問するか会話から推測
- **開発環境**: IDE、OS、既存ツールチェーン
- **チーム構成**: 個人開発 / チーム開発 / 外部委託

**不明な場合は簡潔に質問する（1回で収集する）。**

### Step 3: 技術スタック案の作成

以下の評価軸で **3つの案** を作成する：

| 評価軸 | 説明 |
|--------|------|
| 学習コスト | 習得にかかる時間と難易度 |
| 開発スピード | プロトタイプ完成までの速さ |
| エコシステム | ライブラリ、ドキュメント、コミュニティの充実度 |
| 拡張性 | 将来の機能追加・スケールへの対応力 |
| 運用コスト | ホスティング、保守の手間とコスト |

**3つの案の例:**

1. **推奨案**: バランス重視、一般的なベストプラクティス
2. **軽量案**: 最小構成、学習コスト低、立ち上がり最速
3. **本格案**: 拡張性重視、プロダクション移行を見据えた構成

### Step 4: ユーザーへの提案

各案を以下の形式で提示する：

- 構成の概要（1-2文）
- 主要技術とその選定理由
- メリット・デメリット
- おすすめの対象者

### Step 5: 選定結果の出力

ユーザーが選定したら、`docs/tech_stack.md` にテンプレートに従って出力する。

## 出力形式

```markdown
# 技術スタック

## 選定方針
...（テンプレートに従う）
```

## 注意事項

- **流行より適切さ**: 最新技術より、要件に適した技術を優先する
- **プロトタイプであることを意識**: 過度な設計を避け、素早く動くものを目指す
- **ユーザーの経験を尊重**: 全く未経験の技術ばかりの構成は避ける（1-2個の新技術に留める）
- **判断材料の提示**: 技術の良し悪しではなく、トレードオフを客観的に説明する
