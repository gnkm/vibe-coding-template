# プロトタイプ開発

## 概要

実装計画に基づいてプロトタイプを開発するコマンドです。タスクを1つずつ実行し、**動くものを最短で作る** ことを最優先とします。

## 前提条件

- PRD があること（参照: `docs/prd.md`）
- 技術スタックが決まっていること（参照: `docs/tech_stack.md`）
- 設計書があること（参照: `docs/architecture.md`）
- 実装計画があること（参照: `docs/plan.md`）

**いずれかが不足している場合は、先に該当ドキュメントの作成を依頼する。**

## 手順

### Step 1: ドキュメントの確認

以下のドキュメントを確認し、実装に必要な情報を把握する：

| ドキュメント | 確認内容 |
|------------|---------|
| `docs/prd.md` | 機能要件、受け入れ基準 |
| `docs/tech_stack.md` | 採用技術、ライブラリ |
| `docs/architecture.md` | コンポーネント構成、ディレクトリ構成、データモデル |
| `docs/plan.md` | タスク一覧、完了条件、依存関係 |

### Step 2: 進捗の確認

実装計画（`docs/plan.md`）を確認し、現在の進捗状況を把握する：

- **現在のフェーズ**: Phase 1 / 2 / 3 のどこか
- **完了済みタスク**: チェック済みのタスク
- **次に着手すべきタスク**: 依存が解決されている未完了タスク

### Step 3: タスクの実行

次のタスクを実行する。実行時は以下を守る：

1. **タスクの完了条件を確認** してから着手する
2. **関連ファイル** に記載された対象ファイルを操作する
3. **1タスク = 1コミット** を目安にする
4. 完了したら **動作確認** を行う

### Step 4: 完了条件の確認

タスク完了後、以下を確認する：

- [ ] 完了条件を満たしているか
- [ ] エラーや警告が出ていないか
- [ ] 既存の機能が壊れていないか（リグレッション確認）

### Step 5: 計画の更新

タスク完了後、`docs/plan.md` の該当タスクにチェックを入れる。

```markdown
| # | タスク | 完了条件 | 関連ファイル | 依存 | 状態 |
|---|--------|---------|-------------|------|------|
| 1 | プロジェクト初期化 | package.json 生成 | `package.json` | - | ✅ |
```

### Step 6: 繰り返し

Step 2 〜 5 を繰り返し、フェーズごとの完了チェックを行う：

| フェーズ | 完了基準 |
|---------|---------|
| Phase 1 | アプリケーションが起動し、画面が表示される |
| Phase 2 | コア機能が E2E で動作する（**最優先**） |
| Phase 3 | PRD の機能要件をすべて満たす |

**Phase 2 の完了を最優先ゴールとする。**

## 実行モード

### 通常モード（デフォルト）

1タスクを実行し、完了を確認してから次に進む。

```
/develop
```

### 一括モード

複数タスクを連続で実行する（依存関係は自動で考慮）。

```
/develop Phase 1 を完了してください
```

### 特定タスク指定

特定のタスクのみを実行する。

```
/develop タスク #3 を実行してください
```

## 注意事項

- **完璧より動くもの**: 細部にこだわりすぎず、まず動く状態を作る
- **Phase 2 を死守**: 最小動作版の完成を最優先とし、それ以降は調整可能
- **小さく進める**: 大きな変更は分割して、こまめに動作確認する
- **詰まったら報告**: 30分以上詰まったら状況を報告し、計画の見直しを検討する
- **計画との乖離に注意**: 実装が計画と大きく異なる場合は `docs/plan.md` を更新する
- **コミットはこまめに**: 動作確認できた状態でこまめにコミットする
